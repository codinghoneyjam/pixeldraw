# UI 및 저장 형식 개선 조사·계획

## 목적과 조사 범위

이 문서는 UI/입력/저장 개선 요청 9개를 현재 구현에 대조하고, 호환성을 지키는 실행 순서와 완료 기준을 정한다. 이번 변경은 계획 문서화까지만 다룬다. 코드 및 저장 스키마는 변경하지 않았다.

주요 구현 경계는 [index.html](../index.html), [base 스타일](../style_base.css), [picker 스타일](../style_picker.css), [polish 스타일](../style_polish.css), [색상 패널](../src/features/color/panel_color_wheel.js), [도형 옵션](../src/features/shape/panel_shape_options.js), [파일 작업](../src/ui/actions/file_actions.js), [직렬화](../src/io/serialize.js), [벡터 직렬화](../src/io/serialize_vector.js)다. UI·저장 계약은 [UI 명세](ui.md), [I/O 명세](io.md), [도구 명세](tools.md)를 따른다.

## 현재 상태와 항목별 계획

### 1. 좌측 패널 구획·접기·반응형·스크롤

**현재:** 색상과 브러시는 좌측 패널의 별도 섹션이지만 색상·팔레트·최근색은 한 섹션 안에 있다. 공용 접기 기능은 `data-collapsed` 및 `aria-expanded`를 동기화하고 상태를 저장하지만 본문은 즉시 `display:none` 처리되어 부드러운 접힘은 없다. 좌우 폭은 240px/260px 고정이며 패널 자체에는 세로 스크롤이 있지만 좁은 화면 대응은 제한적이다.

**계획:** 색상 조작, 팔레트, 최근색, 브러시를 독립된 이름 전용 헤더가 있는 접이식 구획으로 분리한다. 본문은 높이/가시성 애니메이션으로 접고, `aria-expanded`와 키보드 조작을 유지한다. 패널 폭은 viewport에 맞춰 제한하고 내부는 콘텐츠 높이와 독립적으로 스크롤되게 한다. 좁은 viewport에서는 캔버스 최소 폭과 패널 접근성을 함께 보장할 반응형 전환 규칙을 둔다.

**완료 기준:** 네 구획이 각각 독립적으로 접히고 상태가 유지된다. 좁은 창에서도 헤더와 필수 조작부가 잘리지 않으며 좌우 패널 스크롤이 동작한다. `prefers-reduced-motion`에서는 접기 애니메이션을 줄이거나 제거한다.

### 2. 레이어 선택 색상과 호버 맥동

**현재:** 레이어 선택 배경은 붉은색 wash이며 선택 모서리 표식은 툴바·브러시 프리셋·레이어 등이 공용 `--sel-red`를 쓴다. 호버는 단순 배경색 전환이다.

**계획:** 레이어 선택 배경과 모서리 표식에 별도의 푸른 계열 토큰을 적용하고, 다른 선택 표식의 붉은색은 유지한다. 좌측 메뉴·레이어 행 호버는 배경 밝기가 어두워졌다 밝아지는 짧은 맥동으로 통일한다. 선택 상태, hover, focus-visible이 서로 가려지지 않게 우선순위를 정의하고 reduced-motion에서는 정적 강조로 대체한다.

**완료 기준:** 붉은색 선택 표식은 오른쪽 레이어에만 남지 않고 푸른색으로 바뀌며, 팔레트·툴바의 기존 선택 상태는 회귀하지 않는다. 마우스와 키보드 focus 모두 같은 항목을 식별할 수 있다.

### 3. 색상환 배치와 색상 입력 필드

**현재:** 색상환과 SV 사각형은 176px 원 안에 겹쳐 있고, RGB/알파/HEX 필드는 기존 CSS 그리드 배치다. 전경·배경 슬롯은 별도 행에 있다.

**계획:** 전경·배경 슬롯 옆에 색상환을 배치하고 원 크기를 현재보다 약 25% 줄이는 안(약 132px)을 기준으로 링·SV 크기를 같은 비율로 계산한다. 폭이 좁으면 슬롯과 색상환을 다음 행으로 넘긴다. R/G/B/Alpha/HEX는 각각 한 행인 5행 세로 배치로 바꾸고, 입력 너비와 라벨은 패널 폭에 맞춘다.

**완료 기준:** 100%/축소/확대 표시와 좁은 패널에서 색상환 및 SV 선택 영역이 잘리지 않는다. 다섯 필드가 세로로 안정적으로 정렬되고 HEX와 채널 값의 입력·반영 동작이 보존된다.

### 4. SV 컬러픽커 포인터 동작

**현재:** 포인터 좌표를 캔버스 `getBoundingClientRect()` 기준으로 정규화하고 0–1로 clamp하며, 드래그에는 Pointer Capture를 사용한다. 정적 코드만으로 특정 y 좌표 이하의 오동작 원인은 확정할 수 없다. 표시 CSS 크기와 canvas bitmap 크기, 테두리를 포함한 경계, 포인터 캡처 중 요소 밖 이동을 실제 브라우저에서 분리 검증해야 한다.

**참고 조사:** 오픈소스 [react-colorful의 Interactive 구현](https://github.com/omgovich/react-colorful/blob/master/src/components/common/Interactive.tsx)은 요소 경계 기준 상대좌표를 clamp하고, 드래그 이동 및 종료 이벤트를 요소 밖까지 추적한다. 현재 구현과 큰 원리는 같으므로 이를 그대로 복제하기보다 좌표 경계와 종료 동작의 차이를 비교한다.

**계획:** 문제를 재현하는 viewport/브라우저/포인터 좌표를 기록하고, 상단·하단·모서리 및 요소 밖으로 드래그하는 브라우저 테스트를 추가한다. canvas의 실제 콘텐츠 박스(테두리 제외)와 bitmap 좌표 간 변환을 명확히 하고, 포인터 종료·취소·capture 상실을 한 번만 commit하는지 검증한다. 테스트가 특정 y 임계값에서만 실패하는지 확인해 원인에 해당하는 최소 수정만 한다.

**완료 기준:** SV 네 모서리가 일관된 색 경계를 만들고, 아래쪽에서도 값이 역행하거나 튀지 않는다. 드래그를 영역 밖으로 이어가도 clamp가 안정적이며 pointerup/cancel/lost capture 후 상태와 최근색 기록이 한 번만 확정된다.

### 5. 40색 팔레트와 최근색 8칸

**현재:** 기본 팔레트 32색은 PICO-8 계열·회색·추가 채도색 조합이고, 최근색 고정 칸 수도 팔레트 길이에 종속되어 32칸이다. 최근색 저장 상한은 별도로 32다.

**계획:** 팔레트 데이터는 정확히 40색으로 재구성한다. 무지개 hue 순서가 한눈에 이어지도록 배열하고, 실사용 중성색·어두운/밝은 변형과 자주 쓰는 기본색을 포함하되 반복/유사색을 줄인다. 최근색 UI 셀 수와 표시 상한은 8로 정하고, 저장 데이터는 기존 키를 유지하면서 오래된 항목을 로드 시 8개로 제한한다. 팔레트/최근색은 별도 접이식 구획으로 둔다.

**완료 기준:** 팔레트 40개와 최근색 슬롯 8개가 고정 크기로 표시된다. 색 선택, 우클릭 보조색 적용, 중복 제거, 최근색 순서 및 기존 설정 데이터 복원이 유지된다.

### 6. 두 상태 옵션 표현

**현재:** 도형 채움/테두리는 라디오 두 개를 세그먼트 버튼처럼 표시한다. 비율 고정과 스냅은 독립적인 체크박스다.

**계획:** 상호 배타적인 두 값 설정은 현재값이 하나만 강조되는 단일 토글 버튼으로 표시하고 클릭할 때 반대 값으로 전환한다. 버튼 텍스트/접근성 이름은 현재 상태와 다음 동작을 명확히 전달하며, 선택 색상은 흰색·푸른색 계열로 구분한다. 서로 독립적인 체크박스는 이 변환 대상에 포함하지 않는다.

**완료 기준:** 테두리↔채움이 한 버튼에서 왕복되고 키보드와 스크린리더에서 현재값을 알 수 있다. 저장되는 설정값과 도형 렌더 결과는 기존과 같다.

### 7. 다각형 정점 입력

**현재:** 캔버스 클릭으로 정점을 추가하고, 3개 이상일 때 첫 점 근처 클릭 또는 Enter로 배치 종료한다. Escape는 마지막 정점을 되돌린다. 확정 후에는 정점 핸들 드래그와 전체 이동이 가능하지만, 옵션바의 정점별 수치 목록은 없다.

**계획:** 다각형 도구에 번호가 있는 정점 목록을 제공한다. 각 정점의 X/Y를 직접 입력·수정하고, 정점 추가/삭제를 명시적인 동작으로 제공한다. 캔버스 클릭 추가, 실시간 미리보기, Enter 확정, Escape 취소는 유지하되 첫 점 근접 클릭으로 암묵적으로 닫히는 동작은 보조 동작으로 낮추거나 제거한다. 작은 viewport에서는 목록을 스크롤 가능한 도구 패널로 둔다.

**완료 기준:** 정점 순서와 좌표가 목록·미리보기·확정 결과에서 일치한다. 3개 미만 입력은 확정되지 않고, 추가/삭제/수정 후 undo·redo 및 기존 다각형 렌더 테스트가 통과한다.

### 8. 도구 전환 시 깜박임

**현재:** `activeTool` 변경은 툴바 pressed 상태와 옵션 섹션 가시성을 바꾼다. CSS에는 선택된 툴 버튼의 300ms pulse가 있고, 메뉴바는 이 설정 변경의 직접 구독자가 아니다. 따라서 툴 버튼 애니메이션은 관찰 가능한 후보지만, 상단 메뉴바 깜박임까지 설명하지 못하며 근본 원인은 미확정이다.

**계획:** 실제 깜박임을 브라우저에서 재현해 DOM 노드 교체, 레이아웃 크기 변화, 포커스 이동, animation 재실행, renderer repaint를 구분한다. 도구 전환 전후 메뉴바/옵션바의 bounding box와 DOM identity를 기록하고, 필요하면 Performance/Rendering 추적을 남긴다. 원인과 연결된 단일 경로만 수정하고 선택 툴 pulse는 전환당 1회만 재생되게 한다.

**완료 기준:** 반복 도구 전환 중 메뉴바 노드·위치·크기가 안정적이고 화면 깜박임이 없다. 옵션 영역만 필요한 범위에서 바뀌며 reduced-motion 설정도 존중한다.

### 9. 읽기 쉬운 저장과 레이어/명령/청크 포맷

**현재:** 기본 `.draw.json`과 레이어 JSON은 JSON v2이며 `JSON.stringify` 기본 출력으로 한 줄 저장된다. 픽셀은 비어 있지 않은 32×32 청크를 PNG/base64로 보관한다. 별도 vector JSON은 현재 래스터를 청크별 단색 사각형/픽셀로 추출해 내보내며, 원래의 선·원·사각형·브러시 작업 이력을 보존하지 않는다. 기본 JSON 로더는 vector 레이어를 지원하지 않는다.

**계획:** 저장 옵션을 다음 세 가지로 분리하고 각 포맷의 목적을 UI에 표시한다.

- **읽기 쉬운 문서 JSON:** 기존 v2 스키마와 호환되는 들여쓰기 JSON. 레이어·청크 객체는 여러 줄로 정렬하고 큰 PNG/base64 페이로드는 항목당 한 줄로 둔다.
- **명령 레이어:** 선·사각형·타원·다각형 등 편집 의도를 레이어별 명령 배열로 저장한다. 모든 편집 작업을 이 형식으로 왕복 보존하려면 그리기 시점부터 안정된 명령 기록이 필요하다. 기존 래스터를 사후 추출한 명령은 근사 변환으로 표시해야 한다.
- **순수 청크:** 렌더 픽셀의 손실 없는 보관/복원에 최적화된 형식. 기존 PNG 청크 JSON을 사람이 읽는 포맷과 구분하고, 압축·크기·호환성 측정 후 JSON 청크 또는 바이너리 컨테이너를 결정한다.

컴파일은 명령 레이어를 픽셀 청크로 렌더링하고, 디컴파일은 픽셀을 가능한 명령으로 추정한다. 두 경로는 보장 수준이 다르므로 디컴파일 결과의 손실/근사 여부를 표시하고, 무손실이라고 약속하지 않는다. 포맷 식별자와 버전을 분리하고 기존 `.draw.json` 로드는 계속 지원한다. 스키마 검증, 파일 크기 제한, 취소/진행 표시, 레이어 단위 내보내기/가져오기 및 round-trip 비교를 함께 설계한다.

**완료 기준:** 세 형식을 명시적으로 저장/열기 할 수 있다. 기존 v2 문서의 픽셀 해시와 레이어 메타데이터가 그대로 복원된다. 명령→컴파일 결과는 기준 렌더와 픽셀 동등성을 만족하고, 청크→컴파일/복원은 바이트 또는 픽셀 동등성을 만족한다. 디컴파일은 근사 변환으로 구분되며 명령별 결과를 테스트한다.

## 실행 순서

1. **기준선 및 재현:** 좁은/넓은 viewport와 포인터 동작을 브라우저에서 기록한다. 특히 SV 이상 동작과 메뉴바 깜박임은 수정 전에 독립 재현 케이스를 만든다.
2. **색상 패널 구조:** 독립 접이식 구획, 반응형 폭/스크롤, 슬롯 옆 소형 색상환, 세로 필드 배치를 함께 적용한다. 팔레트 40색/최근 8칸 및 레이어 전용 선택색을 이어서 적용한다.
3. **입력과 상태 표현:** 재현 테스트로 확정한 포인터 좌표 수정, 2상태 토글, 다각형 정점 목록을 각각 좁은 단위로 구현한다.
4. **깜박임 제거:** 전환 추적에서 확인된 원인만 수정하고 메뉴바 안정성 회귀 테스트를 추가한다.
5. **저장 포맷 설계 검증:** 먼저 명령 레이어의 표현력과 명령 기반 편집 기록 범위를 작은 기술 검증으로 확정한다. 이후 버전 스키마·마이그레이션·선택 UI·컴파일/디컴파일·파일 크기 성능 순으로 확장한다. 이 단계는 다른 UI 변경과 별도 리뷰 가능한 큰 작업으로 유지한다.

## 검증 기준

- **UI/접근성:** 좁은 창·일반 창에서 접기, 스크롤, 포커스, 키보드 동작과 reduced-motion을 확인한다. 기존 `tests/ui_smoke.test.mjs`, `tests/optionbar_sections.test.mjs`에 회귀 검증을 보탠다.
- **색상/포인터:** 40/8 셀 수, 색상 슬롯/필드 동기화, 사각형 경계와 drag-out/취소 동작을 검증한다.
- **도형:** 정점 수·순서·좌표 변경 후 기존 `tests/shape_polygon_tool.test.mjs` 및 래스터 골든 테스트를 통과시킨다.
- **시각 안정성:** 도구를 연속 전환하면서 메뉴바 bounding box와 DOM identity가 유지되는지 브라우저 테스트로 확인한다.
- **저장:** 기존 `tests/io_basic.test.mjs`와 `tests/e2e_session.test.mjs`의 왕복 검증을 유지하고, 신규 포맷별 픽셀 해시·메타데이터·역호환 테스트를 추가한다.

## 조사 결론 및 결정이 필요한 지점

- 컬러픽커와 깜박임의 구체 원인은 정적 코드 조사만으로 확정하지 않는다. 재현 조건과 브라우저 테스트를 먼저 고정한다.
- 명령 레이어는 현재 vector export와 같은 기능이 아니다. 원본 편집 의도를 보존하려면 편집 기록 모델과 저장 스키마 확장이 필요하며, 기존 래스터의 디컴파일은 근사 변환이다.
- 파일 확장자/포맷 이름, 순수 청크의 JSON·바이너리 선택, 명령 이력의 범위는 구현 전 기술 검증에서 결정한다. 기존 `.draw.json` 호환성은 유지한다.
