## 현재 판단

아틀라스는 ATL-1~9 명세에 따라 레이어/합성 슬롯 시트, 64셀, 슬롯당 64레이어, 정수 셀 치수, margin/padding, metadata 복원, PNG 그리드 분할, 슬롯 편집, 대형 시트 백그라운드 내보내기와 진행률/취소, CLI JSON 패치를 지원한다. 2026-10-30 GUI는 그리드 배치·프리뷰/저장·선택 슬롯 레이어를 별도 네이티브 창으로 분리하고 동일 초안을 실시간 공유한다. PNG 셀 RGBA 및 레이어 JSON 보존을 회귀 테스트한다. 취소는 셀 렌더링 경계에서 처리되고 파일 쓰기 직전에도 검사한다. PNG 인코딩 도중에는 압축이 끝날 때까지 기다릴 수 있다. 선·도형을 편집 가능한 객체로 유지하거나 외부 도구와 벡터 호환하는 기능은 이 아틀라스 명세의 범위가 아니다.

2026-10-29 확인: ATL-1~9 범위의 레이아웃 영속화, metadata 왕복, grid slicing, 셀→레이어 편집 점프, 슬롯 임시 편집/확인 시 단일 undo, 드래그·복제·이름 검증, 대형 시트 비동기 내보내기/진행률/취소가 구현됐다. `dtAt` PNG의 정확한 셀 RGBA 왕복과 margin/padding 복원, 레이어 JSON의 픽셀·속성 보존, 셀별 진행/취소 테스트가 통과했다. `cargo test --workspace` (engine 369 + integration tests, app 216, CLI 10), `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --all -- --check`, `cargo check --workspace --all-targets` 통과.

최근 발견·수정: 아틀라스 다이얼로그가 레이아웃을 프레임마다 문서에 즉시 쓰고 있어 **취소해도 저장 상태가 바뀌는 버그**가 있었다. 변경은 다이얼로그 초안에 두고 확인 시에만 검증·커밋하도록 바꿨다. 그리드 PNG 가져오기는 문서 교체를 명시적으로 확정하는 기존 별도 흐름을 유지한다.

선·도형 객체 ID/핸들 편집과 AI diff/preview는 아틀라스 워크벤치 명세 바깥의 별도 제작 편집기 확장이다.

> ATL-3 GUI 확인: 실제 릴리즈에서 `outputs/gems_atlas_128.png`(1024×128)를 분할해 `Cell 01`–`Cell 08` 레이어 8개와 8셀 미리보기를 생성했다. 격리 프로필의 새 문서에서 교체 확인이 뜨지 않는 것도 확인했다.
> ATL-4 구현/GUI 확인: `AtlasLayout`과 출력 미리보기에 바깥 여백·셀 간격을 추가하고 `dtAt`을 v3로 올렸다. v1/v2는 두 값이 0인 것으로 읽는다. 릴리즈 GUI에서 CLI가 만든 144×144 PNG(64px 셀, 2×2, margin 4, padding 8)를 다시 열어 그리드와 두 값이 복원되는 것을 확인했다. 당시 engine atlas 22개와 app 왕복 2개 테스트, `cargo check --workspace --all-targets`, `cargo build --workspace --release` 통과. 이후 2026-10-28 전체 workspace 테스트도 통과했다.

> 2026-10-28 추가: 합성 슬롯 복제 버튼을 넣었고 레이어 순서를 유지하며 원본 다음에 복제되도록 했다. CLI `edit`는 정수 좌표 픽셀 쓰기, Rust 엔진 모양 래스터화, 레이어 속성/순서, 아틀라스 레이아웃 편집을 처리한다. 패치는 전체를 복사본에 적용하고 하나라도 실패하면 결과를 쓰지 않으며, JSON schema 검증 뒤 저장한다. 결과는 레이어별 변경 픽셀 수와 최소 경계 상자를 반환한다. 셀 상한을 문서의 레이어 상한과 맞춘 64로 높여 8×8 애니메이션 시트의 가져오기/내보내기를 지원한다. CLI 10개, 슬롯 UI 7개, 엔진 아틀라스 23개, 64셀 그리드 가져오기 1개 테스트가 통과했다. 전체 workspace 테스트/check, release build도 통과했다. 릴리즈 CLI로 에셋 복사본의 픽셀·선·레이어 속성·아틀라스 레이아웃을 바꿔 저장하고, 평탄화 및 v3 atlas export/inspect를 검증했다. 릴리즈 GUI에서 합성 슬롯 복제를 3셀 프리뷰로 확인하고 취소해 테스트 변경을 버렸다.

## 실제 에셋 제작에서 막히는 지점

ATL-1~9 워크벤치 흐름은 구현됐다. PNG 압축 단계에서는 취소 요청을 받아도 압축이 끝날 때까지 기다릴 수 있다.

1. ATL-3에서 외부 PNG를 셀 크기·행/열·오프셋·간격 기준으로 미리 보고 레이어로 가져오는 경로를 추가했다. 상한을 문서의 최대 레이어 수와 같은 64셀로 확장했다.
2. ATL-4에서 출력 패딩/마진과 v3 metadata를 추가했다. 일반 PNG로 내보내면 Pixeldraw 그리드 복원 정보가 없으므로 다른 도구와 교환할 때는 `dtAt` 포함 PNG를 보관해야 한다.
3. 셀을 눌러 원본 레이어를 바로 열고 선·도형을 조정하는 연결이 없다. PNG로 가져온 셀은 래스터 레이어라 원본 도형의 제어점을 복원하지 못한다.
4. 합성 슬롯은 드래그 재정렬·복제·이름/레이어 구성·방향 버튼을 지원하고, 확인 시 하나의 undo 명령으로 저장된다. 이름은 비어 있거나 중복되거나 64자 초과면 거부한다.
5. 크기 조절은 픽셀을 최근접 이웃으로 리샘플한다. 미리보기는 전체 레이아웃을 포함한 캐시 키를 사용한다.

다음 기능은 ATL-9 진행률/취소다. 객체 단위 도형 편집과 AI 픽셀 diff/자동화는 별도 후속 계획이다.

- 검증: 엔진 atlas 14 + 앱 왕복/워크벤치 6 + CLI 7 + PNG large/chunk 테스트.

## 1. P0 — 왕복을 닫는다

### ATL-1. 레이아웃 영속화 — 구현 및 전체 workspace 테스트 통과

**문제**: `AtlasLayout`은 UI 상태/CLI 옵션에만 있다. `.draw.json`을 다시 열면 모드·열·셀·슬롯·preset이 사라진다.

**할 일**
- `Document.atlas: Option<AtlasLayout>` 추가(직렬화는 optional, 비어 있으면 생략).
- `document_to_json`/`json_to_document`/검증 허용 키/픽스처를 함께 수정.
- `AtlasState::from_app`은 `doc.atlas`가 있으면 그것을, 없으면 현재처럼 `AtlasLayout::from_document`를 쓴다.
- 워크벤치의 편집은 문서 상태를 바꾸는 명령 경로로 보내 저장/undo 대상이 되게 한다.

**수용 기준**
- 아틀라스 문서를 JSON으로 저장→열기하면 모드/열/셀/슬롯 순서/preset이 그대로다.
- atlas 필드가 없는 기존 2.0.0 문서는 지금과 동일하게 열린다.
- JSON 저장과 PNG(`dtAt`) 저장이 같은 레이아웃을 복원한다.

### ATL-2. PNG 가져오기에서 슬롯 복원 — 구현 및 전체 workspace 테스트 통과

**문제**: 가져오기는 슬롯당 1레이어로 베이크한다(의도된 동작). 그러나 `AtlasState`는 문서 레이어에서 레이어 모드로 다시 만들어져, 합성 슬롯 구조가 사라진다.

**할 일**
- `open_atlas_image`가 `dtAt`의 `mode`/`preset_all`/`columns`/`cell`/슬롯 이름·순서로 `AtlasLayout`을 만든다.
- 각 슬롯은 방금 만든 베이크 레이어 1개를 가리킨다(`merged=false`, 이름 유지).
- 가져온 문서에 그 레이아웃을 저장해 워크벤치가 합성 모드로 다시 열리게 한다.

**수용 기준**
- 3슬롯 합성 시트 → 가져오기 → 워크벤치: 합성 모드, 3셀, 이름/순서 동일.
- 다시 내보낸 시트의 셀 픽셀이 원본과 동일(리샘플 없는 셀 크기 기준).
- v1 메타데이터는 레이어 모드로 열린다(현행 유지).

## 2. P1 — 저작 워크벤치

### ATL-3. 메타데이터 없는 PNG 그리드 슬라이스 — 구현, GUI smoke 및 전체 workspace 테스트 완료

- 진입점: 아틀라스 다이얼로그의 `PNG 그리드 분할…`.
- 입력: 셀 W×H, 열 수, 빈 셀 정책(빈 레이어 유지/건너뛰기).
- 추가 입력: 원본 시작 오프셋 X/Y와 셀 사이 간격 X/Y. 선택 영역과 분할선을 원본 위에 표시한다.
- 셀 수 64 초과는 거부한다(엔진 공통 아틀라스 상한). 결과는 셀 크기 문서 + 셀당 레이어이며, 32px 미만 축은 편집기 청크 규칙에 맞춰 투명 패딩한다.
- 메타데이터가 있는 Pixeldraw PNG는 기존 복원 경로로 보낸다. 일반 PNG는 미리보기/확정 전까지 현재 문서를 바꾸지 않는다. 저장하지 않은 변경이 있으면 새 문서 교체를 한 번 더 확인한다.
- 수용: 1280×128 → 128×128 10레이어, 빈 셀 정책대로 동작.

### ATL-3a. 독립 행·열과 빈 칸 보존 — 코드 반영, 전체 workspace 테스트 통과

- 열과 행을 각각 입력한다. 행 자동 모드는 현재 셀 수를 채우고, 고정 행은 남는 칸을 투명 셀로 저장한다.
- 고정 그리드 크기와 슬롯 수를 `dtAt` 및 문서 JSON에서 복원한다. 그리드 용량 초과는 조용히 자르지 않고 오류로 알린다.
- GUI에서 셀 너비/높이를 1px 단위 정수 입력으로 분리하고, px 단위는 입력칸 밖에 표시한다. 문서와 크기가 다르면 최근접 픽셀로 비율을 유지해 맞춘다는 점을 알린다.
- 합성 모드의 빈 칸을 클릭해 해당 위치까지 슬롯을 만들 수 있고, 슬롯이 많아도 고정된 창 높이 안에서 스크롤한다.
- 수용: 4×2 중 5셀을 PNG 저장/가져오면 마지막 3칸은 투명하고 그리드가 4×2로 복원된다.

### ATL-4. 패딩/마진 — 구현, GUI roundtrip smoke 및 전체 workspace 테스트 완료

- `AtlasLayout`에 `padding`/`margin` 추가. 시트 크기 = `margin*2 + cols*cell + (cols-1)*padding` (행도 동일).
- `dtAt` v3에 두 값을 기록하고 기존 v1/v2 파일은 0으로 읽는다.
- 베이크·GUI 프리뷰·PNG 복원에서 같은 원점 공식을 사용한다. CLI는 `--margin`/`--padding`을 받는다.
- 수용: 시트 크기·메타데이터·가져오기 오프셋이 일치하고, 최대 예산 초과 시 파일을 쓰지 않는다.

### ATL-5. 셀 편집 점프 — 기본 경로 구현, 셀 매핑 검증 남음

- 레이어 모드에서 셀 선택 후 `선택한 레이어 편집` → 해당 레이어 활성화 + 다이얼로그 닫기.
- 합성 모드는 "이 셀은 베이크된 결과입니다" 안내(소스 레이어 편집은 ATL-2 이후 별도 결정).
- 수용: 선택한 셀에 매핑된 레이어가 활성화된 채 캔버스로 돌아온다. 취소/Esc는 상태를 바꾸지 않는다.

### ATL-6. 엣지 가드

- 셀/슬롯이 64개를 넘으면 **조용히 자르지 않고** 오류로 처리.
- CLI에서 `preset_all` + 사용자 슬롯 수가 64칸 그리드 용량을 넘으면 마지막을 버리지 말고 오류.
- 비정렬 셀 크기는 GUI/CLI에서 허용한다. PNG의 셀 크기는 메타데이터에 그대로 보존하고, 가져온 편집 문서는 엔진의 청크 정렬 규칙을 따른다.
- 빈 문서/0슬롯/0셀 오류 메시지 고정.
- 각 항목에 회귀 테스트 1개 이상.

## 3. P2 — 다듬기

- **ATL-7 슬롯 undo**: ATL-1로 문서 상태가 된 뒤 추가/삭제/재정렬/병합을 `CompositeCommand` 1스텝으로.
- **ATL-8 슬롯 UX**: 구현 — 슬롯 배치 타일 드래그(타일·시트 셀에 위치 교환), 슬롯 복제·삭제, 이름 중복/길이 검증, 선택 슬롯의 레이어 스택 ▲▼ 및 행 드래그 재정렬. 다음 후보: 키보드 이동.
- **ATL-9 대형 시트**: 프리뷰 캐시 키에 레이아웃 전체 포함, 64 Mi px 근처에서 진행 표시/취소.

## 5. 불변식 (깨면 안 됨)

- `dtAt` v1은 계속 읽는다. 버전을 올리면 이전 버전 reader를 유지한다.
- 64셀 / 셀당 64레이어 / 64 Mi px 예산은 GUI·CLI 공통.
- PNG 가져오기는 **시트 크기 문서를 만들지 않는다** — 항상 셀 크기 문서.
- 베이크 경로는 `pixel_engine::atlas` 하나만 쓴다(GUI/CLI 중복 구현 금지).
- CLI의 JSON 필드(`ok`, `sheet`, `cell`, `cells`, `metadata`)는 추가만 하고 이름을 바꾸지 않는다.
